Los pesos de un modelo son matrices de números. El **formato de fichero** determina cómo se almacenan en disco, qué información de metadatos acompañan, y qué runtime puede cargarlos. Elegir el formato incorrecto puede significa que el modelo no cargue, que sea más lento de lo necesario, o que se necesite más memoria de la disponible.

## Los formatos más importantes

### safetensors (el estándar actual)

Creado por Hugging Face como alternativa segura y rápida a los pickles de PyTorch. Es el formato de referencia para compartir pesos en el ecosistema abierto.

```
modelo.safetensors  ← tensor data + metadata JSON en el mismo fichero
config.json         ← arquitectura (capas, heads, hidden_size…)
tokenizer.json      ← vocabulario y reglas de tokenización
```

- **Seguro**: no ejecuta código arbitrario al cargar (a diferencia de `.pt` con pickle)
- **Rápido**: mmap nativo, carga sin copias innecesarias
- **Compatible**: `transformers`, `diffusers`, `vLLM`, `llama.cpp` lo leen
- **Particionado**: modelos grandes se dividen en `model-00001-of-00003.safetensors`

### GGUF (llama.cpp y familia)

Formato binario de llama.cpp que combina pesos, metadatos de la arquitectura y el tokenizador en **un único fichero**. Diseñado específicamente para inferencia en CPU y GPUs de consumo.

```
qwen2.5-7b-instruct-Q4_K_M.gguf  ← todo en uno, con cuantización incluida
```

- El nombre del fichero codifica la cuantización: `Q4_K_M`, `Q8_0`, `F16`…
- Lo usan Ollama, LM Studio, GPT4All
- No es el formato de entrenamiento: se convierte desde safetensors

<Callout type="note" title="GGUF no es una cuantización">
GGUF es el contenedor. Q4_K_M, Q8_0 o F16 son las cuantizaciones que van dentro. Un fichero GGUF puede contener pesos en cualquier precisión. Lo explica en detalle <Concept id="quantization">cuantización</Concept>.
</Callout>

### AWQ y GPTQ (cuantizaciones precomputadas)

Formatos de pesos ya cuantizados en 4 u 8 bits con métodos que preservan mejor la calidad que el redondeo simple:

- **AWQ** (Activation-aware Weight Quantization): protege los pesos más sensibles. Compatible con vLLM y transformers. Ficheros con `-AWQ` en el nombre.
- **GPTQ**: cuantiza columna a columna con calibración. Compatible con transformers, AutoGPTQ, vLLM. Ficheros con `-GPTQ` en el nombre.

```python
# Cargar un modelo AWQ con transformers
from transformers import AutoModelForCausalLM
model = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-7B-Instruct-AWQ")
```

### MLX (Apple Silicon)

Formato de Apple para modelos que corren en chips Apple Silicon (M1–M4) usando el framework MLX. Los modelos se convierten de safetensors y corren en la GPU integrada con memoria unificada.

```bash
# Convertir y ejecutar con mlx-lm
mlx_lm.convert --hf-path Qwen/Qwen2.5-7B-Instruct --mlx-path mlx_model --quantize
mlx_lm.generate --model mlx_model --prompt "Hola, ¿cómo estás?"
```

### ONNX (interoperabilidad)

Open Neural Network Exchange: representación del grafo de computación que permite exportar un modelo de PyTorch y ejecutarlo en runtimes como ONNX Runtime, TensorRT, o en el navegador con `transformers.js`.

## Cuándo usar cada formato

| Caso de uso | Formato recomendado |
|---|---|
| Compartir en Hugging Face Hub | safetensors |
| Inferencia local CPU/GPU de consumo | GGUF (Q4_K_M para balance calidad/velocidad) |
| Inferencia en servidor (vLLM) | safetensors + AWQ/GPTQ si se necesita int4 |
| Mac Apple Silicon | MLX |
| Inferencia en navegador / móvil | ONNX |
| Fine-tuning | safetensors (pesos base) + adapter en safetensors |

## El pipeline de formatos

```
Entrenamiento (BF16) → safetensors
       ↓
Cuantizar con llama.cpp → GGUF (Q4_K_M)
       ↓
Subir a HF Hub / Descargar con Ollama
```

La mayoría de usuarios descarga GGUF ya cuantizado de Hugging Face sin pasar por la conversión manual.
